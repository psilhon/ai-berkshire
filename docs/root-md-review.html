二、发现的重叠与冗余

重叠 1：README「各 Skill 详细介绍」↔ SKILLS-GUIDE.md（最值得合并）

证据

  • README 369-595 行（约 226 行）逐 skill 详细介绍：/investment-research、/investment-team、/investment-checklist、/industry-research、/industry-funnel、/news-pulse——但只覆盖 6/17
  • SKILLS-GUIDE.md 已是完整使用指南（17 canonical + 3 契约外全登记 + 选择建议路由表），README 的详细介绍是其真子集
  • README 头部「Skills 一览」速查表（169-224 行）与 SKILLS-GUIDE 功能分类表也重叠

方案：README「各 Skill 详细介绍」整节（369-595）压缩为一句 + 链接指向 SKILLS-GUIDE.md；「Skills 一览」速查表保留（快速导航有价值）。README 从 684 行降至 ~460 行，消除 ~200 行重复。

重叠 2：CONTEXT.md（6 条术语的骨架）

分析

CONTEXT.md 仅 45 行、词汇表 6 条术语，自述"骨架版"。它是 docs/agents/domain.md（Matt Pocock skills 模板）引用的领域入口，但项目实际已沉淀大量领域术语（13 契约、lean-v1、双源镜像、self-check 等）未收录。

方案（二选一）：

  • A. 扩充：按当前项目状态补全词汇表（建议，保留独立入口）
  • B. 合并：把 6 条术语并入 CLAUDE.md 新增「领域词汇」节，删除 CONTEXT.md，同步更新 docs/agents/domain.md 引用（改动 2 处）

重叠 3：CLAUDE.md ↔ AGENTS.md（刻意双文件，不合并）

说明

两者内容有交集（双系统管线、研究质量规则、目录结构），但项目明确约定「CLAUDE.md 管 Claude Code，AGENTS.md 管 Codex，改流程时两边同步」——这是 刻意设计（各客户端读取各自文件），合并会破坏 Codex 侧约定。保留。

非重叠（保留理由）

  • CHANGELOG.md：发版记录，守卫豁免史实档案，禁止动
  • CODE_OF_CONDUCT / SECURITY / CONTRIBUTING：GitHub 社区标准件，自动识别/被引用，保留
  • ai_CLAUDE.md：记忆文件定位独立（用户画像/历史/教训），与 CLAUDE.md 指令互补

三、精简合并方案

方案 A（推荐）：README 瘦身 + CONTEXT 扩充

操作对象内容影响
瘦身 README.md 删除「各 Skill 详细介绍」整节（369-595，~226 行），替换为：各 Skill 的完整使用说明见 SKILLS-GUIDE.md（17 canonical + 3 契约外全登记）。 README 684→~460 行；需确认无死链引入；test 检查 ACTIVE_DOCS 不含 REMOVED_SKILLS 与「20 项」字样，删除后更干净
扩充 CONTEXT.md 补录 lean 时代术语：契约 13 单元 / lean-v1 / 单源双镜像 / self-check / substance 地板 / mark-failed / register-summary 等 仅文档，无引用断裂

方案 B（可选激进）：CONTEXT.md 合并进 CLAUDE.md

操作对象内容风险
合并 CONTEXT.md → CLAUDE.md 6 条术语并入 CLAUDE.md 新「领域词汇」节；删除 CONTEXT.md；docs/agents/domain.md 引用改指 CLAUDE.md 改动 2 文件 + 1 引用；docs/agents/domain.md 是 Matt Pocock 模板，改后与上游模板分歧

方案 C（不推荐）：合并 CLAUDE.md + AGENTS.md

风险

破坏「Claude 管 CLAUDE.md / Codex 管 AGENTS.md」的客户端契约；Codex 侧 skills 生成物 adapter note 明确引用 AGENTS.md；合并后任何一侧客户端读不到自己的规则。不改。
