# v3.3.2 全量分析可靠性热修复设计

## 目标

在不改变 Contract v2、Result Bundle v1、13 项业务契约和 WorkBuddy 生产入口的前提下，修复 v3.3.1 评估确认的可靠性、状态机、派发模板与 HTML 安全缺陷，并以完整回归测试和发布说明形成 v3.3.2。

成功标准：

1. 非法嵌套 Result Bundle 在任何正式产物写入前被拒绝。
2. provenance 合并异常不得修改正式文件或 manifest。
3. 包含失败业务单元的运行可确定性终结为 `FAILED`，不再停留在 `PARTIAL`。
4. 派发模板覆盖 capability 声明和 N/A 证明，attempt artifact 不得自报已接受。
5. HTML 不生成危险链接或可注入属性，标题、公司代码和数据截止日准确。
6. Markdown 有序列表闭合正确；`##` 与 `###` 之间仅有空行时仍能输出专项诊断。
7. `investment-checklist` 方法论不再与 Contract 的字节地板冲突。
8. `bash scripts/check.sh`、生成物同步检查、差异检查和发布审计全部通过。

## 范围

### 包含

- Result Bundle v1 的无依赖、递归嵌套校验。
- Gate ingest 的提交顺序修正。
- Gate finalize 的失败终态修正。
- Runtime 派发模板修正。
- HTML 渲染安全、元数据和列表修正。
- 章节专项诊断的空白行兼容。
- 方法论与生成 Codex skill 同步。
- v3.3.2 changelog、release notes 和回归测试。

### 不包含

- 不恢复 v3.3.0 删除的 7 个 skill。
- 不恢复 Codex/Claude Code 的全量生产编排入口。
- 不修改 Contract v2 或 Result Bundle v1 的版本号。
- 不新增第三方依赖。
- 不拆分 `full_analysis_gate.py` 或引入新的渲染框架。
- 不改写旧 tag 或旧 release。

历史 SemVer 和平台兼容性问题只能在 v3.3.2 升级说明中明确披露；补丁版本不尝试回滚既有架构决策。

## 设计

### 1. Result Bundle 深度校验

在 `tools/full_analysis_gate.py` 中增加受限 JSON Schema 递归校验器，执行当前 `tools/full_analysis_result_schema.json` 使用的关键字：

- `type`
- `required`
- `additionalProperties`
- `properties`
- `items`
- `const`
- `enum`
- `pattern`
- `minLength`
- `minimum`
- `minItems`
- `uniqueItems`

校验错误必须包含 JSON 路径，例如 `$.fact_updates[0] 必须为 object`。现有跨字段业务规则继续保留在 `validate_result_bundle()`，Schema 校验先于业务规则执行。

不引入 `jsonschema` 依赖，保持项目零额外安装要求和 Apple Silicon 原生兼容。

### 2. Ingest 提交边界

ingest 分为三段：

1. 完整只读校验：schema、状态、路径、hash、字节、章节、角色备忘录。
2. 内存准备：深复制 manifest，在副本上完成 skill 状态更新和 provenance 合并；这一阶段不得写正式文件。
3. 持久化提交：原子复制正式产物和角色备忘录，最后原子保存已经准备好的 manifest。

本次热修复保证所有确定性校验和 Python 数据处理异常都发生在正式文件复制前。跨多个文件的操作系统级全事务不在本补丁范围内，但复制失败不得写入新 manifest。

### 3. 失败终态

区分两个集合：

- 成功终态：`PASS`、`PASS_WITH_LIMITATIONS`、`NOT_APPLICABLE`
- 完成终态：成功终态加 `FAIL`

finalize 顺序：

1. 有 `PENDING`、`LEASED`、`RUNNING` 等未完成单元：设置 `PARTIAL` 并拒绝。
2. 所有单元完成且至少一个 `FAIL`：设置 run 为 `FAILED`、追加 `run_finalized` 事件、输出失败单元并返回非零。
3. 全部为成功终态：继续 summary、Audit、Review、snapshot 和 APPROVED 流程。

失败运行不要求总结、Audit 或 Review，因为它不具备准出资格。

### 4. 派发模板

`RESULT_BUNDLE_TEMPLATE` 调整为：

- attempt artifact 使用 `formal: false`、`accepted: false`。
- 增加 `capability_records: []`。
- 增加 `not_applicable: null`，说明 N/A 时替换为包含 `predicate`、`fact_id`、`alternative` 的对象。
- 明确 evidence 数组是否非空以当前 skill 的 `evidence_rules` 为准，不要求无契约需求的 skill 制造计算或命令回执。
- 保持 `role_runs` 不由 Agent 自证。

### 5. HTML 安全与忠实性

保持标准库实现：

- 所有页面元数据使用带引号的 HTML escaping。
- 链接仅允许 `http`、`https` 和 `mailto`；其他协议渲染为纯文本。
- URL 属性执行引号转义，禁止事件属性注入。
- 公司和代码读取 `manifest["company"]`。
- 数据截止日读取 `manifest["run"]["as_of"]`，不再使用 summary 登记时间。
- 列表状态记录实际标签，分别闭合 `ul` 和 `ol`。
- HTML 仍是非阻断派生件，不进入 manifest 或 Audit/Review digest。

### 6. 诊断和方法论一致性

`##` 专项诊断查找下一个非空行；若为 `###`，输出缺少正文的精确错误。

`skills/investment-checklist.md` 删除硬编码的 3000 字节要求，改为以 Contract 的当前防坍塌地板为唯一机器真源。运行同步脚本更新生成的 Codex skill。

## 测试策略

采用 TDD，每项先观察失败再实现：

1. malformed `fact_updates` 被 schema 拒绝，正式路径不存在，manifest 保持 `PENDING`。
2. provenance 准备异常不写正式文件。
3. FAIL run 终结为 `FAILED`，不要求 summary/Audit/Review。
4. next-work 模板包含 capability/N/A 字段，artifact 初始状态正确，证据说明与 Contract 一致。
5. HTML 拒绝 `javascript:` 和属性注入，转义元数据，显示正确公司、代码和 `as_of`。
6. 有序列表生成匹配的 `<ol>...</ol>`。
7. 空白行后的 `###` 被专项诊断。
8. 方法论中不存在与 Contract 冲突的固定字节下限。
9. 完整运行 `bash scripts/check.sh`。

## 发布与回滚

开发分支为 `codex/fix-v3.3.2`。本地验证通过后提交精确文件、推送并创建 PR。仓库没有自动发布 workflow；PR 合并到 main 后，从最新 main 创建 annotated tag `v3.3.2`。按照项目发布安全规则，tag 推送由用户执行一次最终确认；远端 tag 出现后再创建 GitHub Release。

回滚方式：

- PR 合并前：关闭 PR，不影响 main。
- GitHub Release 前：不推 tag。
- Release 后发现问题：不重写 tag、不 force push，另发更高补丁版本。

## 风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---:|---:|---|
| 递归校验器与现有 schema 关键字不一致 | 2 | 3 | 用当前 schema 全量遍历测试，并覆盖合法 canary |
| 提交顺序改变导致既有成功 ingest 回归 | 2 | 3 | 保留现有 e2e，并补 PASS/PWL/N/A/FAIL 路径 |
| HTML 安全处理损失合法链接 | 2 | 2 | 明确允许协议并测试中文、查询参数、锚文本 |
| FAILED 终态改变调用方退出码预期 | 2 | 2 | release notes 明确失败终结语义和非零退出码 |
| Skill 源与生成包漂移 | 1 | 2 | 运行 sync 与 `--check`，统一检查阻断发布 |
