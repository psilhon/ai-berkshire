# v3.3.4 公司索引可靠性修复设计

## 目标

在不改变 Contract v2、13 项业务契约、APPROVED 准出语义和现有报告内容的前提下，修复 v3.3.3 新增 HTML 展示件与公司索引中的路径隔离、并发写入、数据分类、渐进增强和转义缺陷，并形成可发布的 v3.3.4。

成功标准：

1. 临时仓库或其他 checkout 中的运行只更新其自身公司索引，不修改源码 checkout 的 `local/Company/index.html`。
2. 新运行统一写入 `local/Company/`；既有大小写目录无需迁移，索引从实际 `run_root` 推导。
3. 并发重建索引时不存在旧快照覆盖新快照或半写文件。
4. 同一公司多个运行只展示最新一次，覆盖公司数和 APPROVED 数按公司口径统计。
5. 北交所、等待、关注、回避结论归类准确；免责声明和含义不明确的 `PASS` 不改变结论。
6. manifest 损坏被明确报告，不再静默伪装成正常总结。
7. JavaScript 不可用时，报告正文和索引卡片仍然可见。
8. `base_label` 等动态文本经过正确 HTML 转义。
9. `bash scripts/check.sh`、生成物同步检查、差异检查和隔离回归测试全部通过。

## 范围

### 包含

- Gate 根据当前 `run_root` 定位公司根目录。
- 新运行目录的 `Company` 大小写统一。
- 公司索引的跨平台互斥锁、原子写入和统一重建入口。
- 单公司 HTML 展示件的原子写入。
- 最新运行选择、公司级计数、北交所板块和结论分类修正。
- manifest 损坏的显式警告。
- 报告页与索引页的无 JavaScript 降级。
- `base_label` HTML 转义。
- v3.3.4 changelog、release notes 和回归测试。

### 不包含

- 不移动、重命名或删除既有 `local/` 数据。
- 不改写既有研究报告和 v3.3.3 tag。
- 不改变 Contract、Result Bundle、Audit、Review 或 APPROVED 规则。
- 不把索引纳入 Gate 准出条件。
- 不引入第三方依赖、数据库或前端框架。
- 不拆分 `full_analysis_gate.py`，不重构无关运行时逻辑。
- 不恢复完整的历史运行导航；索引仍只展示每家公司当前报告。

## 设计

### 1. 运行目录与索引归属

`build_run_root()` 把新运行放在 `<repo>/local/Company/<code>-<company>/<run>/`。

`_rebuild_company_index(root)` 不再从 `TOOLS_DIR` 推导输出目录，而是使用当前运行的结构：

- `root.parent` 是公司目录。
- `root.parent.parent` 是该运行实际所属的公司根目录。

索引生成器代码仍从当前 checkout 的 `scripts/build_company_index.py` 加载，但扫描目录和输出目录均来自实际 `run_root`。这样临时仓库、worktree、大小写敏感文件系统和旧的小写目录都按实际位置工作，无需数据迁移。

函数必须验证 `root`、公司目录和公司根目录都存在；无法推导时打印明确警告并保持展示件非阻断语义。

### 2. 统一索引事务

`scripts/build_company_index.py` 继续负责扫描和 HTML 构建，并增加统一重建函数：

```python
def rebuild_index(base: Path, output: Path | None = None) -> dict:
    ...
```

Gate 和 CLI 都调用该函数。函数在一个互斥锁临界区内完成：

1. 获取 `<base>/.index.lock`。
2. 重新扫描报告。
3. 构建完整 HTML。
4. 写入输出文件同目录的临时文件。
5. `flush`、`fsync` 后使用 `os.replace()` 原子替换。
6. 释放锁并返回 `index`、`companies`、`bytes`。

锁实现复用 `tools/full_analysis_runtime.py` 的标准库策略：POSIX 使用 `fcntl.flock`，Windows 使用 `msvcrt.locking`。不新增依赖。`--check` 保持只读，不获取写锁、不写文件。

单公司 HTML 也通过 Gate 内部的原子文本写入 helper 落盘，避免中断时留下半文件。

### 3. 公司口径与元数据

`collect(base)` 每个公司目录只选择运行目录名称字典序最大的有效总结报告。Gate 的运行名以 `YYYYMMDD-HHMMSS-<hash>` 开头，因此字典序等价于最新运行顺序，并且不依赖本地时区或文件 mtime。

每个公司仅产生一行：

- `total` 等于唯一公司行数。
- `approved` 等于最新运行状态为 APPROVED 的公司数。
- 旧运行文件保持不变，只是不在首页重复展示。

manifest 存在但 JSON 无法解析时：

- `status` 设置为 `MANIFEST_ERROR`。
- 收集精确 manifest 路径到 warnings。
- CLI 在 stderr 输出警告；Gate 记录警告但不阻断 HTML 展示件。

### 4. 板块和结论分类

板块规则增加北交所：

- 代码带 `.BJ`，或数字代码以 `4`、`8`、`920` 开头：`北交所`。
- 其他既有沪主板、深主板、创业板和科创板规则保持不变。

结论分类继续保持“明确负面 → 明确等待 → 明确正面 → 中性”的优先级，但只使用无歧义短语：

- 回避：`回避`、`否决`、`看空`、`排除`、`不建议买入`、`不参与`。
- 等待：`等待`、`等回调`、`等估值`、`等价格`、`观望`、`跟踪`、`观察`、`不买`、`跌出折扣`。
- 关注：`买入`、`持有`、`建仓`、`可买`、`通过`、`建议关注`。

删除免责声明片段 `不构成`、单独的 `PASS` 和单字 `等`。含义不明确的句子回落为中性，由报告中的明确建议决定颜色。

### 5. 渐进增强和 HTML 安全

HTML 核心内容默认可见。页面头部的短脚本在 JavaScript 可用时给根元素增加 `js` 类，动画隐藏规则仅作用于：

- `.js .reveal`
- `.js .card`

脚本失败、CSP 拦截或用户关闭 JavaScript 时，不存在 `js` 类，正文和卡片保持可见。打印与 `prefers-reduced-motion` 继续禁用动画。

`build_index_html()` 在插值前使用 `_esc(base_label)`。公司、代码、结论、路径和状态继续使用既有上下文转义；链接仍保持相对路径。

## 测试策略

采用 TDD，每项先运行单一回归测试观察失败，再实现最小修复：

1. 临时 `run_root` 重建后只生成临时公司根目录的索引。
2. 新运行路径包含 `local/Company/`。
3. 多进程并发重建的最终索引完整、无重复且包含全部公司。
4. 模拟原子写入失败时，旧索引逐字节不变。
5. 同一公司三个运行只收集最新一条。
6. `.BJ` 和北交所数字前缀分类正确。
7. 正向 `PASS` 文案、免责声明和普通“等”字不造成错误结论。
8. 损坏 manifest 产生 `MANIFEST_ERROR` 和明确警告。
9. 无 JavaScript 的默认 CSS 不隐藏报告章节或索引卡片。
10. 恶意 `base_label` 被转义。
11. 完整运行 `bash scripts/check.sh`。

## Profile 与治理

- Profile：`product`。项目存在对外版本、CLI 行为、CHANGELOG 和标签发布。
- 现有 add-ons：`ci`、`release`。
- 本次不启用：`hooks`、`security`、`adr`、`context`、`subagent`、`frontend-qa`。原因是修复不增加依赖、权限、领域概念或浏览器测试框架。
- 保留 `README.md`、`AGENTS.md`、现有 CI 和统一 `scripts/check.sh`；不改变项目骨架。

## 发布与回滚

开发分支为 `codex/fix-v3.3.4`。本地验证后提交精确文件；任何 push、PR、远端 tag 和 GitHub Release 均需单独授权。

发布顺序：

1. 开发分支验证通过并提交。
2. 经授权 push 并建立 PR。
3. PR 合并后从最新 `main` 重新运行完整检查。
4. 用户确认后创建并推送单个 `v3.3.4` tag。
5. 从该 tag 创建 GitHub Release。

回滚方式：

- PR 合并前：不合并或关闭 PR。
- tag 推送前：不创建远端 tag。
- 发布后发现问题：不改写 tag、不 force push，另发更高补丁版本。

## 风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---:|---:|---|
| 目录大小写在不同文件系统表现不一致 | 2 | 3 | 从实际 `run_root` 推导，旧目录不迁移，新目录统一为 `Company` |
| 跨平台文件锁行为差异 | 2 | 3 | 复用项目已有 POSIX/Windows 锁模式并增加并发测试 |
| 最新运行选择隐藏用户想看的历史版本 | 2 | 2 | 只调整首页展示，历史目录和报告原样保留 |
| 结论词表修改改变既有卡片颜色 | 2 | 2 | 使用明确语义样本测试，歧义文本回落中性 |
| 测试误写真实 `local/` 数据 | 2 | 3 | 所有索引集成测试使用临时根目录，并断言输出归属 |
