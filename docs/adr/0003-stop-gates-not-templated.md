# ADR-0003：skill 的 🔴 STOP 门不做共享块模板注入，改由骨架守卫护持

**状态**：Accepted（2026-08-30，/improve-codebase-architecture 评审候选④ 调查后的裁决）

## 背景

2026-08-30 架构评审候选④提出：15 个 skill 文件中共 48 处「🔴 STOP」是同一段话术的复制，
改一次措辞要横跨 15 文件 × 3 条同步链，locality 极差。方案是在 `sync-codex-skills.py`
引入共享块模板注入：源文件写 `{{STOP_GATE}}` 占位，同步时展开为唯一文本。

执行前 trust-but-verify 调查**推翻了两个前提**：

1. **48 处不是同一段文本的复制，只是同构句式。**
   逐条去重后，唯一完全重复的文本只有 2 处（report_audit 发布门）。其余 46 处的
   触发动作、给用户的选项、未确认的后果**全部是各 skill 定制的**，例如：
   - `bottleneck-hunter`：确认"是否全网搜索标的"（"确认全网搜索标的"/"仅先列瓶颈不找公司"）
   - `management-deep-dive`：确认"输出范围与去向"（仅本地保存/分享给指定对象/公开发布）
   - `thesis-tracker`：确认"是否联网取数做追踪检查"
   模板化后每个实例仍需传 4 个参数（动作 / 选项A / 选项B / 后果），共享块几乎不承载内容，
   **杠杆极低**。

2. **仓库外的第三条同步链无法同步改造。**
   三条链中 `~/.workbuddy/berkshire-skill-sync/sync.py`（5446 字节，2026-08-04）位于
   **仓库之外**，由用户手动执行，负责把 `skills/*.md` 装配进日常使用的
   `~/.workbuddy/skills/`。它不做共享块展开。一旦源文件改用占位符，这条链会把
   `{{STOP_GATE}}` 原样拷进用户日常环境，**等于弄坏 15 个在用 skill**。

## 决策

- **不引入**共享块模板注入，**不在** `skills/*.md` 中放置任何占位符。
- 保留「源文件裸读即用」这一性质：它是三条链（含仓库外那条）共同依赖的前提。
- 真正的风险不是重复，而是**被削弱的门**——缺「明确选项」的用户确认门对 Agent 没有约束力
  （用户无从选择），缺停止效力的门形同虚设。故改为机器守卫：
  `scripts/check-stop-gates.py`，已接入 `scripts/check.sh`。

### 守卫的判定口径（重要）

`🔴 STOP` 在本仓有**三种语义**，守卫只强校验第一种：

| 语义 | 判定 | 处理 |
|---|---|---|
| (a) 用户确认门 | 文本含「必须先向用户确认」 | 强校验三要素，缺一即红 |
| (b) 硬停止规则 | 如 `earnings-review` A.7 可信度否决（确定性否决，不向用户征询） | INFO 列出，人工判语义 |
| (c) 散文提及 | 设计说明 / 交叉引用中顺带提到该标记 | INFO 列出，人工判语义 |

三要素：确认义务（必须先向用户确认）+ 明确选项（`明确选项` 或括号内 A/B/C 枚举）
+ 停止效力（`未经确认不得` 或许可式 `获得明确同意后再继续`）。

当前基线：**44 处用户确认门全部达标，4 处非确认类标记列为 INFO**。

## 后果

- 正面：避免一次低杠杆且会破坏用户日常环境的大改；把"门被削弱"变成机器可断言的不变量。
- 负面：纪律文本仍是 15 处副本，改措辞需跨文件——但这是**有代价的正确选择**：
  话术本就各 skill 定制，统一反而丢失上下文。

## 附带教训

评审提出"重复文本应模板化"时，必须先做**去重实证**（`grep -h ... | sort | uniq -c`），
确认是真重复还是同构；并先清点同步链的完整边界，**含仓库外的那些**。
